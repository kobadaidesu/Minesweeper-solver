# Semi-Automatic Minesweeper

**▶ ブラウザで遊ぶ: https://kobadaidesu.github.io/Minesweeper-solver/**

生成AIを補助的に活用しながら、TypeScriptで実装しました。

## 概要

マインスイーパーの盤面を論理推論で補助する、半自動プレイ向けの実装です。

プレイヤーがセルを開くと、確実に安全なセルや地雷だと判断できるセルを自動で処理します。

## 特徴

- 5段階の自動推論で安全なセルや地雷セルを自動判定(1つの数字 → 2つの数字の差 → 地雷配置の全列挙)
- 推論が止まったときは各マスの地雷確率を色の濃さで表示。選ぶのはプレイヤー
- 100×100 のような大きな盤面向けの表示倍率(ズーム)と全体表示
- 初級・中級・上級・大・超大のプリセット
- カスタムボードサイズ対応
- 推論速度調整と高速可視化

## 使い方

1. 依存をインストール

```bash
npm install
```

2. TypeScriptからブラウザ用JavaScriptを生成

```bash
npm run build:web
```

3. `index.html`をブラウザで開く

型チェックのみ実行する場合:

```bash
npm run check:web
```

## 操作方法

- 左クリック: セルを探索
- 右クリック: 旗を立てる/外す
- 新しいゲーム: 入力した幅・高さ・地雷数でリセット
- プリセットボタン: 定番サイズに切り替え
- 解答速度: 推論アニメーション速度を調整
- 最速: 高速可視化モード
- 高速: 1msステップ
- 標準: 100msステップ

## 自動推論ルール

推論は安い順に段階を分けていて、上の段で進めるうちは下の段には降りません。Rule 1/2 は「変化したマスの周りだけ見直す」作業キュー方式なので、盤面の大きさに関係なく変化した量だけの計算で済みます。

### Rule 1: 基本的な開示

数字セルの周りの旗の数が、そのセルの数字と等しい場合、残りの未探索セルを自動的に開きます。

### Rule 2: 基本的なフラグ

数字セルの周りの「未探索セル + 旗」の数が、そのセルの数字と等しい場合、未探索セルすべてに旗を立てます。

### Rule 3: 高度な推論（開示）

2つの数字セルA、Bを比較し、A = B - (Bのみに隣接する未探索セル数) の場合、Aのみに隣接する未探索セルを開きます。

### Rule 4: 高度な推論（フラグ）

2つの数字セルA、Bを比較し、B = A - (Aのみに隣接する未探索セル数) の場合、Aのみに隣接する未探索セルに旗を立てます。

### Final Rule

残り地雷数が0なら残りの未探索セルをすべて開き、残り未探索セル数が残り地雷数と一致した場合は残り未探索セルすべてに旗を立てます。

### Rule 5: 組み合わせ推論

Rule 1〜4 で止まったときだけ動きます。数字に接している未探索セル(フロンティア)を、未探索セルを共有する数字どうしでつないだ成分に分け、成分ごとに地雷の置き方をすべて列挙します。どの置き方でも地雷にならないセルは開き、どの置き方でも地雷になるセルには旗を立てます。残り地雷数と「どの数字にも接していない未探索セル」の数も制約に入れるので、終盤の「残り2個だがこの成分には最大1個しか入らない」のような推論もできます。

### 確率表示

Rule 5 でも決まらないときは、列挙した置き方の数から各セルの地雷確率を求め、色の濃さ(濃いほど危険)で盤面に重ねます(数字に接していないセルは共通の確率)。セルにカーソルを合わせると数値も見られます。開くかどうかはプレイヤーが決め、ソルバーが勝手に賭けることはありません。

## TypeScript版

- `ts/`配下を編集し、`npm run build:web`で`dist/`へ生成します。
- `index.html`は`dist/solver.js`と`dist/minesweeper.js`を読み込みます。
- 推論エンジンは`ts/solver.ts`にあり、Web Worker とメインスレッド(Worker が使えない環境)の両方から同じものを使います。
- 解答速度`0ms`では50ステップごとに描画し、可視化を残しながら高速進行します。
- 高速時は重い演出を間引き、DOM更新をまとめてラグを抑えています。

## 推論エンジンの検証

```bash
npm run build:web
npm run test:solver
```

ブラウザなしで Node だけで動きます。ランダムな盤面を数百局プレイして、地雷を開いたり安全なセルに旗を立てたりしないことを確かめ、小さい盤面では全配置を数え上げた厳密な確率と比較します(誤差は浮動小数点の丸めの範囲)。難易度ごとの勝率も出ます。

同じ盤面200局での成績(推測は「詰まったときにランダムに1マス開く」)。`minprob`は表示される地雷確率が一番低いマスを開いた場合です。

| 難易度 | Rule 1〜4 のみ | Rule 5 あり | Rule 5 + 確率に従う |
|---|---|---|---|
| 初級 9×9 / 10 | 97.0% | 98.5% | 97.5% |
| 中級 16×16 / 40 | 76.0% | 80.5% | 85.0% |
| 上級 30×16 / 99 | 32.0% | 40.5% | 53.5% |

推論1回あたりの時間は上級で 2.3ms → 0.3ms、100×100 / 2000 でも 3ms 程度です。

なお、このゲームは最初のクリックの周り8マスにも地雷を置かないので、「最初のクリックだけ安全」を前提にした研究の勝率(上級で 33〜40%)とは条件が違い、直接は比べられません。

## 参考文献

推論エンジンの設計で参考にしたものです。

- Chris Studholme, [Minesweeper as a Constraint Satisfaction Problem](https://www.cs.utoronto.ca/~cvs/minesweeper/minesweeper.pdf) (2001) — マインスイーパーを制約充足問題として扱い、未確定マスを共有する制約を成分に分けて列挙する手法と、残り地雷数で重み付けした確率計算。Rule 5 と確率表示の元になった考え方
- David J. Becerra, [Algorithmic Approaches to Playing Minesweeper](https://dash.harvard.edu/bitstream/handle/1/14398552/BECERRA-SENIORTHESIS-2015.pdf) (Harvard, 2015) — 単独ルール(single point)と CSP の比較。「安いルールで進めて、止まったら CSP」という段階構成の根拠
- Richard Kaye, Minesweeper is NP-complete, The Mathematical Intelligencer 22(2) (2000) — 盤面の整合性判定は NP 完全。Rule 5 の全列挙に探索予算を付けて、大きすぎる成分は諦める設計の理由
- [minesweepr](https://mrgris.com/projects/minesweepr/) — 確率ベースの推測戦略を10万局でシミュレーションした結果。検証スクリプトで勝率を測る発想の参考
- [minesweepergame.com の論文一覧](https://www.minesweepergame.com/math-papers.php) — 上記を含むマインスイーパー研究のまとめ
